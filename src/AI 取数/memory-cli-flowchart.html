            │

                    │       │

                    └─→ 插入新 seed 行

Schema 提取规则

  • dbtLayer: raw 的模型被跳过
  • 计算列排除在聚合种子之外
  • 标识符列（*_id、主键）排除在数字聚合之外
  • acceptedValues 生成 "Show ... where col is value" 模板
  • relationships 生成 JOIN 查询模板

wren memory index

完整重建内存索引：schema 提取 → 向量化 → 种子生成 → markdown 同步

wren memory index [--mdl/-m MDL_PATH] [--path/-p LANCEDB_PATH] [--instructions/--no-instructions] [--no-seed] [--no-queries]
内部流程
  1. 检测后端：如果是 grep，报告对数后退出（无索引可构建）
  2. 加载 MDL manifest（_load_manifest(mdl)）
  3. 如果 --instructions 且未指定 --mdl：加载项目规则注入 manifest 为 _instructions
  4. 构造 MemoryStore(path=resolved_path)
  5. 调用 mem_store.index_schema(manifest, seed_queries=True)
    → extract_schema_items(manifest) 提取 schema 片段
    → _embed_fn.compute_source_embeddings(texts) 向量化
    → drop 并 recreate schema_items 表（replace=True，全量替换）
    → 生成种子对，删除旧种子，插入新种子
  6. 如果 --no-queries 为 false：
    → load_query_pairs(project_path) 加载 markdown 对
    → mem_store.sync_markdown_queries(md_pairs) upsert + 删除过期
    → 加载遗留 queries.yml（标记 source:legacy）
关键决策点
全量替换 vs 增量更新
schema 索引每次都是全量重建（replace=True），不支持增量。这意味着每次 index 都会重新嵌入所有 schema 片段。
种子查询替换逻辑
source:seed 标签的行会被完全替换，用户对（source:user）不受影响。这确保种子始终与当前 manifest 同步。
正确 / 错误示例
✓ 正确
wren memory index wren memory index --mdl ./target/mdl.json wren memory index --no-seed --no-queries wren memory index --instructions
✗ 错误
wren memory index --mdl /nonexistent/path.json
→ MDL file not found: /nonexistent/path.json
wren memory index --mdl broken.json
→ invalid JSON in broken.json
边界情况
  • 空 manifest（无模型/关系）：schema_items = 0，seeds = 0
  • knowledge/sql/ 目录不存在：静默跳过，加载 0 对
  • queries.yml 损坏：打印警告，命令继续执行
  • 首次运行下载模型到 HF 缓存；后续使用本地缓存
wren memory store

存储单条 NL→SQL 对到 markdown 文件和 LanceDB 索引

wren memory store --nl "natural language" --sql "SELECT ..." [--datasource/-d DS] [--tags TAGS] [--path/-p PATH]
内部流程
  1. 发现项目路径
  2. 写入 markdown 文件到 knowledge/sql/<slug>.md（通过 write_query_markdown）
  3. 尽力索引到 LanceDB（如果 memory extra 可用）：
    → 构造 MemoryStore
    → 调用 store_query(nl, sql, datasource, tags)
    → 嵌入 NL 查询，插入 query_history 表
关键决策点
markdown 文件始终写入
不依赖 memory extra。即使 LanceDB 不可用，markdown 文件也会被写入。LanceDB 索引是尽力而为。
slug 是确定性的
相同 NL → 相同文件名。冲突时添加数字后缀。NL 中的特殊字符被 slugify 为小写字母数字 + 连字符。
正确 / 错误示例
✓ 正确
wren memory store --nl "Total revenue" \ --sql "SELECT SUM(amount) FROM orders" wren memory store --nl "Active users" \ --sql "SELECT * FROM users WHERE status='active'" \ --datasource postgres --tags "users,revenue"
✗ 错误
wren memory store --nl "" --sql "SELECT 1"
→ 创建文件，slug 为空回退到 "query.md"
wren memory store --nl "test"
→ Missing option '--sql'
wren memory recall

语义搜索历史 NL→SQL 对，用于 few-shot 示例召回

wren memory recall --query/-q "search query" [--limit/-l N] [--datasource/-d DS] [--output/-o json|table]
内部流程
  1. 发现项目路径
  2. 通过 get_index(project, path) 获取索引
    → LanceDB: LanceDBIndex → 语义搜索 via store.recall_queries()
    → Grep: GrepIndex → token 重叠 + 子串匹配
  3. 通过 markdown 文件路径注解结果
  4. 打印结果
关键决策点
Grep 评分逻辑
_tokens() 提取 2+ 字符的小写 token
评分 = token 重叠数 × 10 + (整个查询是子串 ? 5 : 0)
线性扫描所有对（<1000 对时很快）
正确 / 错误示例
✓ 正确
wren memory recall --query "revenue by region" wren memory recall --query "orders" --limit 10 --output json wren memory recall --query "users" --datasource postgres
✗ 错误
wren memory recall
→ Missing option '--query' / '-q'
wren memory fetch

检索 schema 上下文，自动选择全文或语义搜索策略

wren memory fetch --query/-q "search query" [--mdl/-m MDL_PATH] [--limit/-l N] [--type/-t model|column|relationship|view] [--model MODEL_NAME] [--threshold N] [--output/-o json|table]
内部流程
  1. 加载 MDL manifest
  2. 构造 MemoryStore
  3. 调用 store.get_context(manifest, query, **kwargs)
    → describe_schema(manifest) 生成纯文本
    → 如果 len(text) ≤ threshold（默认 30000）：strategy="full"
    → 否则：strategy="search"（LanceDB ANN 搜索）
  4. 搜索时按 mdl_hash、item_type、model_name 过滤
关键决策点
全文 vs 搜索阈值
默认阈值 = 30,000 字符 ≈ 8,000 token
CJK 语言更早切换（相同字符数更多 token）
--threshold 0 强制搜索，--threshold 999999 强制全文
全文提供完整上下文但可能超出 LLM 窗口；搜索提供相关片段但可能丢失全局结构
正确 / 错误示例
✓ 正确
wren memory fetch --query "customer revenue" wren memory fetch --query "orders" --type model --limit 3 wren memory fetch --query "amount" --type column --model orders wren memory fetch --query "test" --threshold 5000
✗ 注意
wren memory fetch --query "test" --type invalid
→ 不报错，只是不应用类型过滤
wren memory watch

监控 MDL 和 markdown 文件变化，自动触发重索引

wren memory watch [--mdl/-m MDL_PATH] [--interval/-i SECONDS] [--reindex-on-start/--no-reindex-on-start] [--max-polls N]
内部流程
  1. 如果 grep 后端：拒绝（无衍生索引可监控）
  2. 发现项目路径，验证 --mdl 在项目根目录内
  3. 定义 _reindex() 回调：加载 manifest → index_schema → sync_markdown_queries
  4. 进入 watch_loop：
    → 计算初始指纹（SHA-256 of path+size+mtime_ns）
    → 每次轮询：重新计算指纹，比较
    → 变化时：调用 _reindex()，更新基线
    → 失败时：保持旧指纹，下次重试
    → KeyboardInterrupt：干净退出
关键决策点
指纹计算（无文件内容读取）
SHA-256 of: for each file in sorted(target/mdl.json, knowledge/sql/*.md):
relative_path \0 size \0 mtime_ns \0
仅 stat 调用检测变化（廉价），不读取文件内容
失败重试机制
重索引失败时保持旧指纹，变化待定。下次轮询时如果文件仍变化，会重试。
正确 / 错误示例
✓ 正确
wren memory watch wren memory watch --interval 2.0 --reindex-on-start wren memory watch --max-polls 10
✗ 错误
wren memory watch --mdl /other/project/mdl.json
→ --mdl is outside the watched project root
WREN_MEMORY_BACKEND=grep wren memory watch
→ grep backend: nothing to watch

wren memory forget

从 query_history 表中删除 NL→SQL 对（三种模式）

wren memory forget [--id ID ...] [--source/-s seed|user|view] [--force/-f] [--limit/-n N]
三种模式
  1. 非交互式 + --id：按位置索引删除。--id 和 --source 互斥。
  2. 批量 + --source + --force：按来源标签批量删除。
  3. 交互式（默认）：需要 InquirerPy，呈现 checkbox UI。
关键决策点
位置索引陷阱
_row_id 是未过滤表中的位置索引，每次列表操作可能变化。
ID 超出范围时静默跳过（不报错）。
所有行被删除时删除整个表。
正确 / 错误示例
✓ 正确
wren memory forget --id 0 --id 3 --id 5 wren memory forget --source seed --force wren memory forget # 交互式
✗ 错误
wren memory forget --id 1 --source seed
→ --id and --source cannot be used together
wren memory forget --id 99999
→ "Forgot 0 pair(s)."（静默忽略）
wren memory load

从 YAML 文件批量导入 NL→SQL 对

wren memory load FILE [--upsert] [--overwrite] [--dry-run]
三种导入模式
  1. overwrite：删除相同来源的所有对，然后写入所有
  2. upsert：按 nl_query 去重（后者胜出），删除现有匹配，插入所有
  3. 默认（skip）：对每对，如果精确（nl, sql）匹配则跳过
关键决策点
upsert 去重逻辑
upsert 按 nl_query 去重（不是 sql），最后出现的胜出。这意味着相同 NL 不同 SQL 时，后者覆盖前者。
正确 / 错误示例
✓ 正确
wren memory load queries.yml wren memory load backup.yml --upsert wren memory load export.yml --overwrite --dry-run
✗ 错误
wren memory load nonexistent.yml
→ file not found: nonexistent.yml
wren memory load broken.yml
→ unable to read YAML from broken.yml

wren memory check

检查 markdown 文件和 LanceDB 索引之间的同步状态

wren memory check [--path/-p PATH]
内部流程
  1. 加载 markdown NLS：{p["nl"] for p in load_query_pairs(project)}
  2. 加载已索引 NLS：{r["nl_query"] for r in mem_store.list_queries(limit=1M)}
  3. 加载已索引的 markdown 支持 NLS：按 _MARKDOWN_SYNC_TAG 过滤
  4. 计算：
    → missing = md_nls - indexed_md（在 markdown 中但未索引）
    → stale = indexed_md - md_nls（已同步但 markdown 已删除）
关键决策点
使用 _MARKDOWN_SYNC_TAG 而非 source
使用 origin:markdown-sync 标签识别由 sync_markdown_queries 写入的行。
不使用 source 标签（会错误分类 wren memory load 的对）。
正确示例
✓ 同步
wren memory check # knowledge/sql: 5 pair(s); index: 5 pair(s) # In sync.
✗ 不同步
wren memory check # knowledge/sql: 3 pair(s); index: 5 pair(s) # 2 indexed pair(s) without markdown, stale index, # run `wren memory index`.

查询上下文策略

get_context(manifest, query)
    │
    ├─→ describe_schema(manifest) → text
    │
    ├─→ if len(text) ≤ threshold (30000):
    │       return {strategy: "full", schema: text}
    │
    └─→ else:
            ├─→ manifest_hash(manifest) → mdl_hash
            └─→ _search_schema(query, mdl_hash)
                    └─→ LanceDB ANN search
                        WHERE mdl_hash = ?
                        AND item_type = ?
  • 阈值 = 30,000 字符 ≈ 8K token
  • CJK 语言更早切换
  • --threshold 可调

Markdown 同步协议

sync_markdown_queries(pairs)
    │
    ├─→ load_queries(pairs, upsert=True,
    │       mark_markdown_synced=True)
    │       │
    │       ├─→ 去重输入按 nl_query
    │       ├─→ 准备记录带 _MARKDOWN_SYNC_TAG
    │       ├─→ 删除匹配 nl_query 的现有行
    │       └─→ 插入新记录
    │
    └─→ Forget pass:
            ├─→ 列出带 _MARKDOWN_SYNC_TAG 的行
            ├─→ 找到 nl_query 不在当前 pairs 中的行
            └─→ 删除过期行
  • _MARKDOWN_SYNC_TAG = "origin:markdown-sync"
  • 只有 sync 写入的行有资格被 forget
  • source:user 行不会被 sync 遗忘

Watch 监控循环

watch_loop(project, interval, max_polls)
    │
    ├─→ baseline = "" if reindex_on_start
    │              else compute_fingerprint()
    │
    └─→ while polling:
            ├─→ current = compute_fingerprint()
            ├─→ if current == baseline: skip
            ├─→ reindex()
            │       ├─→ index_schema()
            │       └─→ sync_markdown_queries()
            ├─→ baseline = current (only on success)
            └─→ sleep(interval)
  • 指纹 = SHA-256(path+size+mtime_ns)
  • 无文件内容读取（仅 stat）
  • 失败重试（保持旧指纹）
  • 最小间隔 1.0 秒

Embeddings 后端

OnnxEmbeddings Pipeline:
  1. Load tokenizer (HF cache)
  2. Validate mean pooling
  3. Load ONNX model
  4. Encode: tokenize → session.run
     → attention-masked mean pooling
     → L2 normalize
  5. Batch size: 32

Local-First Loading:
  Try local_files_only=True first
  Fallback to online download
  Model cached per process
  • ONNX: 轻量，无 torch 依赖
  • ST: 需要 torch，更多模型选择
  • 自动检测，优先 ONNX

GrepIndex 搜索逻辑

GrepIndex.search(query):
  tokens = _tokens(query)  # 2+ char lowercase
  for pair in all_pairs:
    pair_tokens = _tokens(pair.nl)
    overlap = len(tokens & pair_tokens)
    score = overlap * 10
    if query in pair.nl.lower():
      score += 5  # substring bonus
  return sorted by score, limit N
  • 无依赖，纯 Python
  • 线性扫描（<1000 对时很快）
  • token 重叠 + 子串匹配

LanceDBIndex 搜索逻辑

LanceDBIndex.search(query):
  vector = embed(query)  # 384-dim
  results = store.recall_queries(
    query=vector,
    limit=N,
    datasource=DS
  )
  return results  # milliseconds
  • 需要 memory extra（lancedb + pyarrow）
  • ANN 搜索，毫秒级
  • 支持 datasource 过滤
  • 嵌入查询是瓶颈
