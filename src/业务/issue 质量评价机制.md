## 昇腾社区单 Issue 处理质量评分卡（参考五维度模型）

### 一、适用范围

- **评价对象**：状态为“已关闭”（Closed）的单个 Issue。
- **评价目标**：衡量该 Issue 从提交到关闭的全链路处理质量。
- **适用场景**：月度/季度抽样评估、维护者绩效参考、优秀案例评选、劣质案例整改。

---

### 二、评分维度与权重（总计 100 分）

| 维度 | 权重 | 核心考察点 |
|------|------|------------|
| 响应与闭环及时性 | 25% | 是否快速响应、是否在合理周期内闭环 |
| 回复内容质量 | **30%** | **回复是否专业、有效、可执行（核心）** |
| 流程规范性 | 20% | 标签、分流、状态流转是否合规 |
| 协作互动质量 | 15% | 处理过程中的沟通深度与响应程度 |
| 知识沉淀贡献 | 10% | 是否留下可复用的文档/PR/FAQ（加分性质） |

---

### 三、单 Issue 详细评分标准

#### 维度一：响应与闭环及时性（满分 25 分）

| 评分项 | 分值 | 评分细则（以该 Issue 实际时间线为准） |
|--------|------|--------------------------------------|
| **首次响应时效** | 10分 | • 从创建到首条非机器人回复 ≤1天 → 10分<br>• ≤3天 → 7分<br>• ≤7天 → 4分<br>• >7天 → 0分 |
| **问题闭环时长** | 15分 | 按 Issue 类型区分（以创建到关闭计算）：<br>**Bug类**：≤7天→15分；≤15天→10分；≤30天→5分；>30天→0分<br>**需求/咨询类**：≤14天→15分；≤30天→10分；≤60天→5分；>60天→0分 |

> **说明**：若该 Issue 因版本排期原因延期关闭，但处理过程中有明确说明且社区认可，可酌情豁免（需人工备注）。


#### 维度二：回复内容质量（满分 30 分）—— **核心维度**

此维度对 Issue 下**所有有效回复**综合评分，重点考察**最终解决方案回复**。

| 评分项 | 分值 | 评分细则 |
|--------|------|----------|
| **问题理解准确性** | 8分 | • 精准定位根因，无偏差 → 8分<br>• 基本理解，但有偏差或猜测 → 4分<br>• 答非所问，完全误解 → 0分 |
| **解决方案有效性** | 12分 | • 提供可直接落地的方案（代码/命令/配置），经确认问题解决 → 12分<br>• 提供有效方向/思路，需用户少量摸索 → 7分<br>• 仅回复“去查文档”或“提给其他模块”，无实质帮助 → 0分 |
| **回复详尽程度** | 6分 | • 包含原理解释 + 操作步骤 + 示例 → 6分<br>• 仅有简要文字说明，无步骤/示例 → 3分<br>• 仅一句话或一个外部链接 → 1分 |
| **沟通态度与专业性** | 4分 | • 专业、尊重、有耐心 → 4分<br>• 中性 → 2分<br>• 冷漠、推诿、不友善 → 0分 |

**该维度一票否决（劣质识别）**：  
若该 Issue 下出现以下任一情况，**维度二直接计 0 分**，并标记为“劣质处理”：
- 全部回复均为“收到”“好的”“已阅”等无实质内容；
- 回复中仅有无效/无关链接，且无任何文字说明；
- 回复中包含攻击性、歧视性或不尊重言论。


#### 维度三：流程规范性（满分 20 分）

| 评分项 | 分值 | 评分细则 |
|--------|------|----------|
| **标签规范性** | 5分 | • 正确标记了类型标签（bug/enhancement/question）和状态标签 → 5分<br>• 缺少任一必要标签 → 2分<br>• 无任何标签或标签错误 → 0分 |
| **分流准确性** | 5分 | • 24小时内分派给正确模块/负责人 → 5分<br>• 超过3天未分流或分流错误后纠正 → 2分<br>• 始终未分流或推诿多次 → 0分 |
| **状态流转完整性** | 5分 | • 状态按 In Progress → Review → Closed 正常流转 → 5分<br>• 状态长期不更新，突然关闭 → 2分 |
| **模板遵循度** | 5分 | • 回复遵循社区模板（如复现步骤、环境信息等）→ 5分<br>• 缺少关键字段 → 2分 |


#### 维度四：协作互动质量（满分 15 分）

| 评分项 | 分值 | 评分细则 |
|--------|------|----------|
| **互动频次与深度** | 6分 | • 有 ≥3 条有实质内容的互动（追问细节、验证方案等）→ 6分<br>• 有 1-2 条实质互动 → 3分<br>• 仅 1 条回复即关闭，无互动 → 1分 |
| **对提交者追问的响应** | 6分 | • 提交者追问后，24小时内给予有效答复 → 6分<br>• 追问后超过3天答复或答复无效 → 2分<br>• 不回应追问 → 0分 |
| **是否主动联动他人** | 3分 | • 主动 @ 相关模块负责人或专家协同处理 → 3分<br>• 独自处理未联动 → 1分 |


#### 维度五：知识沉淀贡献（满分 10 分）

| 评分项 | 分值 | 评分细则 |
|--------|------|----------|
| **是否关联代码 PR** | 4分 | • 关联了修复该 Issue 的 PR，且 PR 已合入 → 4分<br>• 关联了 PR 但尚未合入 → 2分<br>• 无关联 PR → 0分 |
| **是否同步更新文档/FAQ** | 4分 | • 解决方案已沉淀至官方文档或 FAQ → 4分<br>• 仅在 Issue 评论中留存，未同步文档 → 1分<br>• 无沉淀 → 0分 |
| **是否打标典型类型** | 2分 | • 标记为 good-first-issue / help-wanted / 典型问题 → 2分<br>• 未标记 → 0分 |


### 四、综合评分与等级判定

**单 Issue 综合得分 = 五项得分之和（满分 100 分）**

| 等级 | 综合得分 | 标识 | 含义（针对该 Issue） |
|------|----------|------|----------------------|
| **卓越（S级）** | ≥90分 | 🌟 | 响应极快、方案精准可执行、沟通专业、有代码/文档沉淀，堪称典范 |
| **优秀（A级）** | 75～89分 | ✅ | 处理质量高，问题得到有效解决，仅个别细节可优化 |
| **合格（B级）** | 60～74分 | ⚠️ | 基本闭环，但存在响应偏慢、方案不够详细或流程疏漏 |
| **不合格（C级）** | <60分 | ❌ | 存在应付式回复、长期未闭环、方案无效或态度问题，**需整改** |

> **特殊标记**：若某 Issue 触发“维度二一票否决”（劣质回复），无论总分多少，**自动降为 C 级**，并进入人工复核名单。


### 五、单 Issue 评分示例（模拟）

**Issue #1234**：用户报告 MindSpore 在 Ascend 上运行报错，3天后关闭。

| 维度 | 得分明细 | 小计 |
|------|----------|------|
| 及时性 | 首次响应 4小时（10分）；Bug类 3天关闭（15分） | 25分 |
| 内容质量 | 问题理解准确（8分）+ 提供代码修复方案（12分）+ 含步骤说明（6分）+ 态度专业（4分） | 30分 |
| 流程规范 | 标签完整（5分）+ 当天分流（5分）+ 状态正常（5分）+ 模板完整（5分） | 20分 |
| 协作互动 | 互动3次追问环境（6分）+ 追问当日回复（6分）+ 联动另一专家（3分） | 15分 |
| 知识沉淀 | 关联PR已合入（4分）+ 未更新FAQ（1分）+ 未打标（0分） | 5分 |
| **总分** | | **95分（S级）** |


### 六、实施流程（单 Issue 评价闭环）

```
┌─────────────────────────────────────────────────────────┐
│  Step 1：Issue 关闭触发评价                            │
│  当 Issue 状态变为 Closed 时，Bot 自动采集该 Issue     │
│  的所有元数据（时间线、评论、标签、关联 PR）            │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 2：自动初评                                      │
│  Bot 按上述评分卡自动计算各项得分（时效、流程、互动     │
│  频次、是否含代码块/链接等），给出初评等级              │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 3：触发复核规则                                  │
│  • 初评为 S 级或 C 级 → 必须人工复核                  │
│  • 初评为 A/B 级 → 按 10% 随机抽样人工复核            │
│  • 复核重点：内容质量中的“方案有效性”                  │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 4：结果写入 & 公示                              │
│  最终评分写入 Issue 标签（如 quality/S）               │
│  月度生成《单 Issue 质量排行》，公示 S 级和 C 级案例  │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 5：C 级 Issue 整改                              │
│  通知该 Issue 的主要处理人，要求 3 个工作日内           │
│  补充有效方案或重新处理，直至问题真正闭环              │
└─────────────────────────────────────────────────────────┘
```


### 七、配套保障

| 机制 | 说明 |
|------|------|
| **提交者反馈权重** | 若 Issue 关闭时，提交者明确评论“解决了/感谢”，可在维度二额外加 **+2分**（上限不超过30分） |
| **争议申诉** | 处理人对评分有异议，可向 TSC 提起申诉，由 3 人评审小组复核 |
| **月度报告** | 每月发布各维护者处理的 Issue 平均分、S级占比、C级占比，促进良性竞争 |
| **激励挂钩** | S 级 Issue 累计达到 10 个，授予“社区卓越维护者”标识；年度排名前列给予物质/荣誉奖励 |
| **底线红线** | 累计 3 个 C 级（且均为劣质回复）的维护者，TSC 将约谈并重新评估其社区角色 |
