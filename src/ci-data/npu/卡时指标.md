
## 一、指标定义

| 概念 | 含义 | 计算公式 | 用途 |
|------|------|---------|------|
| **占用卡时** | 任务从Pod启动到结束，**占用的NPU卡总数 × 时长**（包含调度、初始化、实际计算全周期） | 占用卡数 × 总运行时长 | 资源预留/计费依据 |
| **使用卡时** | 任务**实际使用**NPU卡的总时长（仅含有效计算时间） | 使用卡数 × 实际计算时长 | 真实资源消耗评估 |
| **占用卡时-使用卡时** | 资源浪费量（调度等待、初始化、闲置等） | 占用卡时 - 使用卡时 | 资源利用率优化参考 |

**单位说明**：所有卡时指标均以 **卡秒** 为单位存储，展示时可换算为 卡时（除以3600）或 卡天（除以86400）。


## 二、任务看板 - 表格展示所需指标

### 2.1 任务占用卡时（Counter类型）

任务从Pod创建到Pod销毁，**占用的NPU卡总数 × 运行时长**。由任务启动器和任务代码共同配合上报。

```json
{
  "version": "1.0",
  "name": "task_card_occupied_seconds_total",
  "desc": "任务累计占用NPU卡总秒数（占用卡数 × 总运行时长），用于计算占用卡时",
  "timestamp": 1786351551389000,
  "data_list": [
    {
      "value": 21600.0,
      "label": {
        "task_id": "workflow-13069-20260908",
        "cluster": "ascend-hk-001-cluster",
        "account": "ascend_infra",
        "env": "cloud",
        "community": "mindstudio",
        "node": "os-node-created-2dq9v",
        "pod_name": "linux-aarch64-a2b3-1-m8kx4-runner-jhxkx-workflow",
        "pr": "vllm-project/vllm-ascend/.github/workflows/_selected_tests_upstream.yaml@refs/pull/13069/merge",
        "project": "参与开源统一资源池-香港-A2(910B3)",
        "npu_type": "910B",
        "region": "香港"
      }
    }
  ]
}
```

**上报方式**：在任务入口处记录开始时间，在任务退出时（或定期检查点）计算 `总运行时长 × 占用卡数`，上报到Prometheus。


### 2.2 任务使用卡时（Counter类型）

```json

  "name": "task_card_used_seconds_total",
  "desc": "任务累计实际使用NPU卡总秒数（实际使用卡数 × 实际计算时长），用于计算使用卡时",
  "timestamp": 1786351551389000,
  "data_list": [
    {
      "value": 14400.0,
      "label": {
        "task_id": "workflow-13069-20260908",
        "cluster": "ascend-hk-001-cluster",
        "account": "ascend_infra",
        "env": "cloud",
        "community": "mindstudio",
        "node": "os-node-created-2dq9v",
        "pod_name": "linux-aarch64-a2b3-1-m8kx4-runner-jhxkx-workflow",
        "pr": "vllm-project/vllm-ascend/.github/workflows/_selected_tests_upstream.yaml@refs/pull/13069/merge",

    }
  ]

```

**上报方式**：在模型加载、训练循环、推理批处理等实际计算逻辑开始和结束时打点，累加计算时长 × 实际使用卡数。

## 六、关键实施步骤：为已有指标增加 task_id 标签

### 6.1 步骤一：Pod 启动时注入 task-id 标签

在 GitHub Actions 中，通过 K8s Pod 模板注入 `task-id` 标签：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-npu-task
  labels:
    task-id: "workflow-${GITHUB_RUN_ID}"  # 从 GitHub Actions 注入
spec:
  containers:
  - name: main
    image: my-npu-image
```

### 6.2 步骤二：Prometheus relabel 配置

修改 Prometheus 采集配置，从 Pod 标签中提取 `task-id` 并添加到所有相关指标中：

```yaml
scrape_configs:
  - job_name: 'npu-exporter'
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      # 1. 从 Pod 标签提取 task_id
      - source_labels: [__meta_kubernetes_pod_label_task_id]
        target_label: task_id
        action: replace
      
      # 2. 保留其他重要标签
      - source_labels: [__meta_kubernetes_pod_name]
        target_label: pod_name
      - source_labels: [__meta_kubernetes_namespace]
        target_label: namespace
      - source_labels: [__meta_kubernetes_node_name]
        target_label: node
```

### 6.3 步骤三：验证

配置生效后，查询验证：

```promql
# 验证 custom_npu_total_used_count 是否带 task_id
custom_npu_total_used_count{task_id="workflow-1234567890"}

# 验证 npu_chip_info_utilization 是否带 task_id  
npu_chip_info_utilization{task_id="workflow-1234567890"}
```

## 八、实现要点总结

| 要点 | 说明 |
|------|------|
| **核心决策** | 任务卡数趋势图**复用 `custom_npu_total_used_count` / `custom_npu_total_occupied_count`**，通过新增 `task_id` 标签实现任务维度筛选，不新增独立指标 |
| **需要新增的指标** | 仅两个 Counter：`task_card_occupied_seconds_total`（占用卡时）、`task_card_used_seconds_total`（使用卡时） |
| **需要加标签的已有指标** | `custom_npu_total_used_count`、`custom_npu_total_occupied_count`、`npu_chip_info_utilization`、`npu_chip_info_hbm_utilization` |
| **标签注入方式** | Pod 打 `task-id` 标签 → Prometheus `relabel_configs` 提取 → 所有相关指标自动带上 `task_id` |
| **卡时 vs 卡数** | 卡时（Counter，累计值）用于表格；卡数（Gauge，瞬时值）用于趋势图 |
| **卡时上报时机** | 占用卡时在任务退出时上报；使用卡时在计算段埋点累加，任务退出时上报 |
